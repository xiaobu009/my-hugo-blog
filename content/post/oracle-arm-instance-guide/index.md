## 为什么第一台机器先开 A1 更好

新账号进控制台，眼前就有两种免费机器可以开，很多人会犹豫先开哪个。我的建议非常明确：**先全力冲 A1，先别管 Micro。**

| 机型 | 配置 | 数量上限 |
|------|------|---------|
| **ARM（VM.Standard.A1.Flex）** | 合计 2 OCPU + 12GB 内存 | 拉满开 1 台，或拆成 2 台各 1 核 |
| AMD（VM.Standard.E2.1.Micro） | 每台 1/8 OCPU + 1GB 内存 | 最多 2 台 |
|  |  | **总共最多 4 台** |

首先两类机器的额度是**分开计算**的，除了硬盘空间共享外，CPU，内存额度互不占用，最高可开4 台实例（2 台 A1 + 2 台 Micro），且A1实例性能远强于Micro实例。所以原因很简单，**A1 抢手，Micro 不抢手。** Micro 你什么时候想开都能开出来，A1 得看运气。热门区域的 A1 资源长期紧张，创建时大概率会弹一个「Out of capacity」的红条。所以正确做法是：一上来把精力全砸在 A1 上，抢到了再回头慢悠悠开 Micro。反过来先开 Micro，纯属浪费时间窗口。

Micro 那两台怎么开，是本系列下一篇的事，这篇我们只盯着 A1。

## 给机器起个名，选对隔间

进入配置页，最上面两栏：

**Name（名称）**：默认会给一个类似 `instance-20260919-1430` 的名字。改成你认得出来的，比如 `arm-main`。这个名字只是控制台里的标签，随时能改，不影响任何功能。

**Create in compartment（在区间中创建）**： 这里是确认选的是你的**根隔间**——通常就是你的账号名或者组织名。就是注册时填写的 Oracle Cloud 账户名称。新账号只有这一个隔间，一般不用动，但如果这里选错了，后面创建出来的机器你可能在列表里找不着。保持刚才那个根隔间不变。

## 挑可用区：能换就多换几个

往下是 Placement → **位置** 区域，里面有个 Availability domain → **可用性域**。

这一栏值不值得折腾，取决于你注册时选的区域（Region）：

- **大多数区域只有 1 个可用区**（显示 AD-1），没得选，直接跳过
- **少数大区域有 3 个可用区**（比如美国东部 Ashburn、西部的 Phonenix、德国法兰克福），显示 AD-1 / AD-2 / AD-3

如果你是后一种情况，这一栏就很有用了。不同可用区的物理机资源是**各自独立**的，AD-1 满了不代表 AD-2 也满。等会儿创建失败的时候，回来换一个 AD 重试，往往比干等着有效得多。这也是我们注册时建议选凤凰城，阿什本的原因。

注册时选的区域是**注册完就锁死、后面改不了**的，所以这里看到几个 AD 就是几个，认命就好。我这里系统选的是AD-3，先保持默认，后面如果提示资源满了再回来换其他区域。

## 换个顺手的系统镜像

系统默认的是 **Oracle Linux** 这个映像。

Oracle Linux 本身没毛病，但对新手不友好——网上的教程、Docker 安装脚本、各种一键脚本，绝大多数是按 Ubuntu 或 Debian 写的，你用 Oracle Linux 会频繁遇到「命令找不着」「包名不对」这类事。

点 Change image（**更改映像**），选 **Canonical Ubuntu**，这里我选了最新的26标准版本。如果你是为了**长期稳定使用 Oracle 免费 ARM A1**，我反而建议你使用 **Ubuntu 24.04 LTS**，因为服务器系统不一定是“版本越新越好”。

有网友分享**ARM A1**机器要选aarch64这个版本，说法没有错。可以选这个版本，也可以选其他版本，Oracle 会判断实例类型，自动为你安装相应的应用。

## 核心一步：把处理器换成 Ampere

**这是整篇最关键、也最容易点错的地方。**

往下找到 shape → **配置** 区域，点 **更改配置** 。

弹窗里按顺序操作：

1. Instance type → **实例类型** 保持 Virtual machine（**虚拟机**）
2. Shape series → **配置系列** 选 **Ampere** —— 就是这一步，千万别停在 AMD 或 Intel 上
3. 下面的列表里勾选 **VM.Standard.A1.Flex**

勾上之后，**点一下左侧的三角图标**，下方**右侧**会冒出**两个三角滑块**：Number of OCPUs → **OCPU数** 和 Amount of memory (GB) → **内存量**。上箭头是增加，下箭头是减少。这里你会看到OCPU最大值80，和内存最大值512，就以为可以创建80CPU和512GB内存的机器。千万不要一冲动就使劲加码，这个指的是最大值，Arm免费实例的最高配置就2OCPU和12GB内存，如果选超了钱包缩小的速度，一定大于你选OCPU的速度。

滑块怎么拉，有讲究：

- **拉满：OCPU = 2，内存 = 12**。一台机器吃掉全部额度，性能最好，适合只想要一台主力机的人。
- **拉小：OCPU = 1，内存 = 6**。剩下的额度留着以后再开第二台。而且——**小规格明显更容易申请成功**。

为什么小规格更容易成功？因为 Oracle 底层是按整块物理资源切分的，要凑出一整块 2 核 12G 的连续空闲资源，比凑出 1 核 6G 难得多。空出 1 核的频率天然就高。

我的建议：**先按 1/6 把机器建出来占住名额**，剩下的额度后面单独再开一台，或者等以后有空闲资源了给现有机器扩容。手里有机器，比死磕满配强。

留意一下，选中 A1.Flex 之后，列表里配置名称的右侧，应该带着 Always Free-eligible（**符合永久免费条件**）的标签。看到这个标签，说明你选对了，滑块也没超额。**如果标签消失了，赶紧回头看滑块是不是拉超了 2 核或 12G**——超一点点就从免费变成按小时计费。

完成后点 **选装配置** 按钮确认。返回基本信息界面后，点 **下一步** 继续。

**安全**页面中什么都不用选，点 **下一步** 继续。

## 网络和 SSH 密钥：唯一一次能下载私钥的机会

### 网络

第一步是设置 Primary VNIC（**主要 VNIC**） 区域。

新账号**首次创建实例**，**主要网络**选 「**创建新虚拟云网络**」，**子网**选 「**创建新公共子网**」。务必勾上「**自动分配公共 IPv4 地址**」，不分配公网 IP 的话，你没法从外网 SSH 连上去。
>**特别注意**：新账户第一次创建实例时 **自动分配公共 IPv4 地址** 这里是灰色的，而且不一定那能开启，如果无法开启，就按照下面Oracle 官方推荐的做法，创建 VCN完成后，再回到 **主要 VNIC** 这里，选 「**选择虚拟云网络**」即可，然后再进行下一步的SSH密钥操作。不然没有公网地址，后面无法访问新建的实例。

**Oracle 官方推荐的做法**：官方文档写的是，第一次创建实例的话，建议先去创建VCN。

1. 菜单 ≡ →「网络」→「虚拟云网络」，点「操作」或「启动 VCN 向导」。也可以从「网络」→「概览」进去。
2. 选「**创建具有 Internet 连接的 VCN**」，再点「启动 VCN 向导」。
3. 填一个 VCN 名称，区间选 eyeblues（根）。IP 地址段那些保持默认就行。
4. 点「下一步」，检查一下，点「创建」。等全部资源都显示完成。

如果**之前已经创建过实例**，VCN已经存在，这里直接选 「**选择虚拟云网络**」即可， VCN（虚拟云网络）和子网参数会自动加载。

### SSH 密钥

这是全篇第二个容易翻车的地方。继续往下，Add SSH keys（**添加 SSH 密钥**） 有几个选项：

**方式一：让 Oracle 生成（新手推荐）**

选 Generate a key pair for me（**为我生成密钥对**），然后立刻点下面的 `Save private key`（**下载私有密钥**）把私钥文件下载下来。

划重点：**这是唯一一次能下载私钥的机会。**页面一刷新、一跳转，这个私钥就永远拿不回来了，机器也就永远连不上，只能删了重建。下载完把文件放到一个你记得住的地方，比如 `C:\Users\你的用户名\.ssh\`。顺手也把 **公共密钥**（`Save public key`）下载保存，以后用得着。

**方式二：自己生成的密钥**或者**上传已有的密钥**

如果你已经装了 Git Bash（Mac 用终端），也可以**自己生成一对密钥**，更放心：

```bash
ssh-keygen -t ed25519 -C "oracle-arm"
```

一路回车（密码可以不设）。生成的两个文件默认在 `~/.ssh/` 目录下：`id_ed25519` 是私钥（**绝不外传**），`id_ed25519.pub` 是公钥。

用记事本打开 `.pub` 那个文件，把里面一整行内容复制下来，回到 Oracle 页面选 **Paste public keys**（粘贴公有密钥），粘进去。

> 私钥丢了 = 机器废了。没有找回流程，没有客服能帮你，只能删机重建。现在就想好你要把它存哪。

如果保存过其他Oracle 实例中下载的密钥，这里可用选择第二项 **上传公共密钥文件**，然后将密钥拖到提示的窗口中即可。

SSH 密钥设置完成后，点 **下一步** 继续设置 **存储** 空大小

## 存储

下面的 **Boot volume（引导卷）** 这里保持默认就行，默认约 50GB，这也是 Oracle 允许的最小值。免费存储额度里一共 **200GB**，如果你想创建两台Arm机器每台 50GB，还剩 100GB 留给那两台 Micro 机器，应该够了。当然你也可以自己定义存储磁盘的大小。

> 千万别一次性把引导卷拉满。拉到 200GB 确实还在免费额度内，但你后面就没空间开 Micro 了。

**引导卷性能** 是为了满足不同负载的要求。10 是引导卷的默认值，适合大多数工作负载，20 适合 I/O 要求高的负载，30–120适合大型数据库之类的场景。如果要跑的是一般的服务器或代理，10 VPU 就够用了，保持默认即可，以后可以再编辑调整。
>
特别要注意： A1实例中**只能调大，不能调小**，一旦开的太高，想降档就没可能了。

**调整路径**：左上角菜单 ≡ →「存储」→「块存储」→「右侧菜单中选-引导卷」→ 点右边的「⋯」→「编辑」

存储设置是创建A1实例前的最后一步，设置好后点「**下一步**」。

## 点 Create → 创建，然后做好心理准备

所有配置确认完，滚动到页面最底部，点 Create（**创建**）按钮。

**顺利的话**，页面跳回实例详情页，状态显示橙色的 PROVISIONING（**预配中**），一两分钟后变成绿色的 RUNNING（**运行中**）。恭喜，机器到手了，直接跳到下一节。

到这里**大概率你会看到一条红色报错**：

![API错误，容量不足](/images/arm-001.webp)

```
Out of host capacity. 资源容量不足
```

翻译过来就一句话：这个可用区的 ARM 资源暂时被抢光了。

别慌，这几乎是每个人的必经之路，**不是你操作错了**。尝试下面的三种方法：**换一个可用区（AD-1、AD-2）、把滑块降到 1 核 6G、或者过几个小时换个时间段再点一次 Create**。这三招试一轮下来，多数人能出货。

> 实在不想跟报错较劲的话，也不必死磕。[Vultr](https://www.vultr.com/?ref=9905832) 两块五美金一个月就能开一台，几分钟到手，新用户还送 $300 试用额度。时间也是成本，抢了一周抢不到，不如花顿饭钱把事办了。

## 连上去看看，这机器才算真的是你的

实例状态变成 RUNNING 之后，在实例详情页的 **Instance access** 或 **Primary VNIC** 区域，找到 **Public IP address（公有 IP 地址）**，复制这串数字。

打开 Git Bash（Mac 用终端），把私钥路径和 IP 换成你自己的：

```bash
ssh -i ~/.ssh/id_ed25519 ubuntu@你的公网IP
```

几个容易踩的点：

- 用户名跟镜像走：**Ubuntu 镜像用 `ubuntu`**，Oracle Linux 用 `opc`。用 root 连一定失败。
- `-i` 后面是**私钥**路径，不是公钥，别把 `.pub` 那个填进去。
- Windows 下如果提示 `WARNING: UNPROTECTED PRIVATE KEY FILE` 或 `Permissions too open`，在 Git Bash 里执行 `chmod 600 ~/.ssh/id_ed25519` 再连。

第一次连接会问你是否信任这台主机的指纹，输入 `yes` 回车。看到类似这样的欢迎信息，就是彻底到手了：

```
Welcome to Ubuntu 24.04.3 LTS (GNU/Linux 6.8.0-1030-oracle aarch64)
```

最后那个 **aarch64** 是 ARM 架构的标志，看到它说明你确实开到了 A1，没有手滑选成 AMD。

## 常见报错与解决

| 报错现象 | 原因 | 解决步骤 |
|----------|------|----------|
| `Out of host capacity` | 该可用区 ARM 资源暂时分配满 | 换可用区 / 降到 1 核 6G / 换时间段重试；详见本系列第 5 篇 |
| Shape 列表里找不到 A1.Flex | Shape series 还停在 AMD 或 Intel 上 | 回到 Change shape 弹窗，先把 Shape series 切成 **Ampere** |
| A1.Flex 那行的 Always Free-eligible 标签消失了 | 滑块拉超了 2 OCPU 或 12GB | 把 OCPU 调回 ≤2、内存调回 ≤12，标签会重新出现 |
| 机器建好了但连不上，也找不到 IP | 创建时没勾 Assign a public IPv4 address | 实例详情页 → Attached VNICs → 编辑 VNIC 分配公网 IP；或删了重建 |
| `Permission denied (publickey)` | 用户名错了，或者用的是公钥 | Ubuntu 镜像用 `ubuntu`，Oracle Linux 用 `opc`；`-i` 后面必须跟私钥文件 |
| `Permissions too open` | Windows 下私钥文件权限太松 | Git Bash 里执行 `chmod 600 私钥路径` |
| 私钥下载窗口已经关了，没存下来 | 私钥只能下载一次 | 没有找回办法，只能终止该实例重新创建 |

## 抢到了还得防一手：闲置的机器会被收回去

这条很多教程不讲，但特别坑：**A1 实例放着不用，Oracle 真的会收回去。**

这不是传言，官方文档里写得明明白白。判定标准是连续 **7 天**内同时满足下面三条：

- CPU 利用率（95 百分位）低于 20%
- 网络利用率低于 20%
- **内存利用率低于 20%**（这一条只针对 A1 机型）

三条**必须同时**成立才会被判定为闲置。反过来说，只要有任意一条超过 20%，你的机器就是安全的。

好消息是，这个门槛对 A1 来说其实很好过——**内存那一条是最容易满足的**。你的机器有 12GB 内存，20% 也就是 2.4GB，随便跑个 Docker、挂个小服务、装个面板，内存占用就上去了，根本不用刻意折腾。

所以真正的规避办法就一句话：**抢到之后别晾着，给它找点事做。** 建个站、跑个 RSS 订阅器、挂个下载工具、装个 Nginx 反代，什么都行。真的暂时没需求，起一个常驻的轻量服务占住内存也比空转强。

网上有人教你写脚本定时跑满 CPU 来"保活"，我不建议——那属于人为制造无效负载，反倒更容易撞上滥用检测，赔了夫人又折兵。正常用它，就是最好的保活。

> 另外提一句，被回收的是**实例**，不是账号。但对你来说结果一样惨：机器没了，想重开就得重新去抢一遍 A1。

正常用完全没问题：建站、跑个人服务、装点东西练手、挂个轻量应用，这些都是它该干的活。
